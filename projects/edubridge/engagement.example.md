# Engagement: EduBridge Bangladesh

**Reference, not homework.** The instructor's filled version. Yours goes in `projects/<your-client>/engagement.md`.

**Read the last section first if you read nothing else.** Almost none of this file came from the brief, and all of it decides whether this job is worth doing.

---

## 1. What is in scope?

Four screens, mobile, to high-fidelity, with the states named: tutor search results, tutor profile, booking request, payment. One tokenised Figma file the developer can receive. One working HTML prototype of the booking flow.

Deliverables, not activities. "UX design" is not a scope line; four named screens are.

## 2. What is explicitly out?

- **Video calling.** It entered after the number was agreed, via the client seeing Preply. Designing it is a separate piece of work.
- **Bengali UI strings.** Layouts will not hardcode widths that break under Bengali, so the retrofit stays cheap. Translating and laying out a second language is not in this number.
- **The card path beyond one screen.** SSLCOMMERZ is designed to entry only; its full error handling is phase two.
- **Desktop.** The brief says desktop-first; the market says otherwise, and the agreed answer is mobile. Desktop responsive behaviour is not a deliverable.
- **Tutor-side onboarding.** Never mentioned, and someone will assume it is included.

That last line is why this section exists. The expensive scope is the scope nobody named.

## 3. How many revision rounds, and what counts as one?

Two rounds per screen. A round is **one consolidated set of comments, delivered once.** Three separate WhatsApp messages on three days about the same screen is one round, not three, and it is also how three weeks becomes five.

New screens and new flows are not revisions.

## 4. Who signs off, by name?

**Jamie Thornton.** One name, and this needed asking, because his manager has already sent an opinion through Rafi about Bengali. Two approvers means neither approves and the work sits between them.

## 5. What happens when they ask for something new?

Written estimate before anything starts. One line is enough: *"Happy to take that on. It is roughly N days, which puts it outside the current sprint. Want me to quote it?"*

Not a refusal. A price.

## What this cost to find out

Nothing above is in `brief-v1-client.md`. Here is where it actually came from:

- **One WhatsApp line**, at 7:12pm: *"budget is 3 lakhs for the full design sprint. so roughly 3 weeks of your time. client thinks that covers everything including revisions."* That single sentence is the reason this file exists.
- **Video calling** arrived after the number was agreed. Nobody flagged that as a scope change.
- **Bengali** is "optional" from Jamie and "strongly preferred" from his manager. Unresolved, and therefore priced out until it is.
- **Revision rounds** were never mentioned by anyone, in any message.
- **Sign-off** was never named. It had to be asked for.

**3 lakhs BDT, roughly three weeks.** With video calling, Bengali, and unlimited revisions folded in, that is a loss. With this file agreed up front, it is a normal job.

The design skill and the commercial skill are the same skill here: interrogate what you were handed. This is that skill pointed at the part that pays you.
